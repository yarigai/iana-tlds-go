# iana-tlds-go

Zero-dependency Go module (`github.com/yarigai/iana-tlds-go`, package `ianatlds`) that validates email TLDs against the IANA list. Go port of `@yarigai/iana-tlds`.

- `ianatlds.go`: public API (`ValidateEmail`, `IsValidEmail`, `TLDsList`, `LastUpdated`, `EmailValidation`, `Reason*`).
- `tlds_data.go`: generated by `go generate ./...` (`internal/updatetlds`); never edit by hand.
- CI syncs IANA daily and auto-tags a patch release when the list changes. Manual release: `scripts/release.sh [patch|minor|major]` (pushes a `vX.Y.Z` tag; CI tests it, creates the GitHub release and warms proxy.golang.org).
- Checks: `test -z "$(gofmt -l .)" && go vet ./... && go test -race ./... && go build ./...`.
- Versioning: there is no version file; the git tag is the version. Every completed task that changes the shipped module ends with a release tag (PATCH fixes/refactors/docs, MINOR features/behavior, MAJOR breaking — a v2+ also needs the `/v2` module path). Add a CHANGELOG entry before tagging.

## Sibling repo: keep both in sync (mandatory)

This repo has a JavaScript/TypeScript twin at `/Users/naojamg/Documents/Github/Yarigai/iana-tlds` (npm `@yarigai/iana-tlds`, GitHub `yarigai/iana-tlds`). Its `CLAUDE.md` has the same rule pointing back here.

Any change requested here that touches **behavior, public API, data format, sync pipeline, tests or docs** must be applied in both repos in the same task, each following its own language conventions:

1. Make the change here and in the sibling.
2. Run both check suites (sibling: `pnpm type-check && pnpm lint && pnpm test && pnpm build`).
3. Update both `CHANGELOG.md` files, commit and push both, and release both (here: `scripts/release.sh <bump>`; sibling: bump `package.json` + `pnpm release <bump>`). Versions are independent; use the same bump level.
4. Go-only improvements (performance, idioms, Go-specific docs) are fine as long as the contract below is unchanged. Language-specific files (`go.mod`, `package.json`, tooling) have no counterpart.

### Shared contract (must stay identical)

| JS (`@yarigai/iana-tlds`) | Go (`ianatlds`)                       |
| ------------------------- | ------------------------------------- |
| `validateEmail(email)`    | `ValidateEmail(email)`                |
| `isValidEmail(email)`     | `IsValidEmail(email)`                 |
| `tldsList: string[]`      | `TLDsList []string`                   |
| `lastUpdated: string`     | `LastUpdated` (const string)          |
| `EmailValidation` union   | `EmailValidation` struct              |
| `"invalid_format"`        | `ReasonInvalidFormat`                 |
| `"unknown_tld"`           | `ReasonUnknownTLD`                    |
| `tld: null`               | `TLD == ""` (marshals to `null`)      |
| `src/data/tlds.ts`        | `tlds_data.go`                        |
| `scripts/update-tlds.mjs` | `internal/updatetlds/main.go`         |
| `src/index.test.ts`       | `ianatlds_test.go`, `example_test.go` |

- JSON of a result is byte-identical in both: keys `valid, email, tld, reason`; `tld` is `null` when unparsed; `reason` absent when valid.
- Same parsing rules: last `@`, last `.`, lowercase TLD, same `invalid_format` edge cases.
- Same IANA source, same "skip if list unchanged" sync rule, same `lastUpdated` format (`2006-01-02T15:04:05.000Z`).
- Every test case exists in both suites.
